# Excel 全工作表中英互译功能设计

## 目标

在现有“走货明细管理”应用中增加一个独立的“Excel 中英翻译”工具。登录用户上传一个 Excel 文件后，系统扫描文件内全部工作表，把可翻译的文字在原单元格中补齐中文和英文，并生成一份保持原工作簿结构的新文件供下载。

该工具与现有“走货明细上传处理”相互独立：不解析排模表或外购清单，不创建产品、走货行或其他业务记录，也不改变现有处理流程。

## 已确认的用户体验

- 左侧菜单新增独立入口“Excel 中英翻译”。
- 首版范围包含一个 `.xlsx` 或 `.xlsm` 文件，最大 50 MB；不支持旧版二进制 `.xls`。`.xlsm` 是首版交付要求，但只有宏保真上线闸门通过后才能在页面启用，首版不能以静默降级或改成 `.xlsx` 的方式交付。
- 用户选择文件后先上传并扫描。扫描完成后，页面显示工作表数量和待翻译候选文字数量；用户点击“开始翻译”后再进入队列，并显示处理阶段、适用时的当前工作表、进度、成功数、跳过数和失败数。
- 处理完成后下载新文件；`.xlsx` 输出为 `原文件名_中英翻译.xlsx`，`.xlsm` 输出为 `原文件名_中英翻译.xlsm`。
- 翻译任务和文件不进入产品数据库。等待用户开始的任务和已经结束的任务保留 1 小时；正在运行的任务完成后再开始计算保留期。
- 本机与局域网用户通过现有应用地址使用同一功能，并沿用现有登录鉴权。

## 翻译结果规则

翻译内容保留在原单元格中，新增语言使用 ` / ` 分隔：

- 中文原文：`卡车车身` → `卡车车身 / Truck body`
- 英文原文：`Truck body` → `Truck body / 卡车车身`
- 印尼文或其他非中英文原文：`Nama Produk` → `Nama Produk / 产品名称 / Product Name`
- 已有中文和英文时保持不变；已有原文和其中一种目标语言时只补齐缺少的语言。
- 系统生成的标准分隔格式必须可再次识别。翻译后的文件再次上传时，不得重复追加相同语言。

语言判断分两层进行：

1. 先识别汉字、拉丁字母和系统生成的 ` / ` 分段，判断单元格是否已经包含目标语言。
2. 对无法仅靠字符确定的英文、印尼文或其他拉丁文字，使用翻译服务返回的语言检测结果。模型号等嵌在正常短语中的内容作为短语的一部分保留。

以下内容不翻译：

- 空白、纯数字、日期、布尔值和错误值
- 公式单元格及其缓存显示值
- 纯型号、料号、网址、邮箱、文件路径、单个符号或只有标点的内容

合并单元格只处理实际保存值的左上角单元格。可见、隐藏和非常隐藏的工作表都要扫描，但工作表名称不翻译。

富文本单元格使用其完整显示文字进行判断和翻译。写回时保留全部原有富文本片段及片段样式，只在末尾增加一个继承最后一个非空片段样式的新片段；不得把原富文本压平成普通字符串。如果某种富文本结构无法安全追加，该单元格保留原值并计入失败。

## 输出定位与计算语义

输出文件是用于阅读和传递的双语副本，原文件始终不修改。公式表达式本身必须保持原样，但若公式、查找、数据验证、定义名称或外部关系依赖一个被追加译文的文字单元格，Excel 重新计算后的结果可能发生变化。这是同一单元格追加译文的必然结果，首版不尝试改写依赖公式来维持原计算语义。

扫描阶段统计公式数量。文件包含公式时，页面在开始翻译前和下载结果时显示上述提示；用户仍可继续生成阅读型副本。验收比较公式文本和公式类型是否保留，不把重新计算后的结果完全相同作为验收条件。

## 系统结构

### 前端

新增 `client/src/pages/ExcelTranslatePage.jsx`，并在 `client/src/App.jsx` 注册菜单、标题和页面切换。页面复用 Ant Design 的拖放上传、进度条、状态提示和下载交互，不与现有 `Upload.jsx` 的排模/外购配对逻辑共用状态。

前端只保存当前任务 ID，不保存工作簿内容。上传扫描和翻译处理期间都轮询状态接口；刷新页面时可从本地任务 ID 恢复仍在 1 小时有效期内的任务。任务完成或带警告完成时显示下载按钮；任务失败时显示明确原因并允许重新上传。

页面在开始按钮附近说明：只有去重后的文字会发送到外部翻译服务，完整工作簿、公式、图片和格式不会发送。文件包含公式时同时展示“阅读型双语副本”的计算语义提示。

### 后端

新增独立路由 `server/routes/excelTranslation.js`，挂载到受现有 JWT 中间件保护的 `/api/excel-translations`。核心逻辑按现有项目约定放在 `server/utils/`：

- `server/utils/translationJobManager.js`：任务队列、所有权、状态、进度和过期清理
- `server/utils/excelTranslator.js`：工作簿扫描、翻译映射、写回和结构校验
- `server/utils/translationProvider.js`：对 `google-translate-api-x` 的批处理、语言检测、超时和重试封装
- `server/utils/workbookIntegrity.js`：输入/输出 ZIP 包关键部件与工作簿结构校验

翻译任务使用进程内状态，临时文件放在现有可写上传目录下的 `uploads/translation-jobs/<jobId>/`，不写入现有 JSON 数据库。队列默认一次只运行一个翻译任务，以避免内部应用同时提交大量文本时触发翻译服务限流。服务重启会中断未完成任务；启动和每 10 分钟一次的定时清理都会删除过期临时文件，清理定时器不得阻止 Node 进程退出。

清理期限按状态计算：`ready` 后 1 小时内未启动则过期；`queued`、`translating`、`writing` 和 `validating` 运行期间不清理；进入 `completed`、`completed_with_warnings` 或 `failed` 后重新计算 1 小时保留期。查询或下载不延长期限。

## API 与任务生命周期

所有接口均要求登录，且任务只能由创建它的用户查询和下载。任务 ID 使用不可预测的随机值，文件名只使用清理后的 basename。

### `POST /api/excel-translations`

接收 multipart 字段 `file`，验证扩展名、MIME、ZIP/Office 文件结构、50 MB 压缩文件限制和 512 MB 解压总量限制，把文件写入独立临时任务目录并异步扫描，然后返回 `202 Accepted`：

```json
{
  "jobId": "random-id",
  "status": "scanning"
}
```

扫描只统计工作表、符合跳过规则的候选单元格和去重候选文本，不调用翻译服务。英文、印尼文等需要服务检测的内容在正式处理时才分类，因此页面明确标为“候选数量”，正式总数可能略少。扫描结束后释放工作簿对象，任务进入 `ready`，避免用户停留在确认页面时长期占用整本工作簿内存。

### `POST /api/excel-translations/:jobId/start`

仅允许任务所有者启动处于 `ready` 的任务。接口返回 `202 Accepted`，任务进入单并发队列，并按 `queued → translating → writing → validating` 执行。重复点击不会创建第二个任务；非 `ready` 状态返回 `409 Conflict`。终态为：

- `completed`：全部完成
- `completed_with_warnings`：部分文字失败，输出仍可下载
- `failed`：无法安全生成输出

### `GET /api/excel-translations/:jobId`

返回任务状态和进度：原文件名、当前阶段、工作表总数、公式数量、目标文字单元格数、待处理唯一文本数、适用时的当前工作表、已处理数、成功数、跳过数、失败数、错误摘要和过期时间。成功、跳过和失败按单元格数量统计，唯一文本数单独展示。前端每 10 秒轮询一次，并在 `ready` 或终态停止轮询，避免触发应用现有的全局请求限流。响应不返回工作簿中的原文或译文，避免把文件内容写入浏览器日志。

`scanning`、重新收集和写回阶段可以返回当前工作表；跨工作表去重后的 `translating` 阶段不显示虚假的当前工作表，只显示“翻译中”和唯一文本进度。

若扫描结果没有可翻译文本，任务仍进入 `ready`，页面显示“没有需要翻译的文字”并禁用开始按钮；这不是系统失败，也不生成一份无变化的重复文件。

### `GET /api/excel-translations/:jobId/download`

仅在 `completed` 或 `completed_with_warnings` 时返回输出文件，并按输入类型设置正确的文件名和 Content-Type。下载不会创建产品记录；文件在任务过期前可重复下载。

## 工作簿处理流程

1. 扫描和正式处理阶段都使用 `xlsx-populate` 从上传文件读取现有 OOXML 工作簿，禁止通过 `xlsx` 重新生成整个文件。
2. 扫描阶段逐个检查全部工作表的已用区域，计算符合规则的普通字符串及富文本候选单元格数量和去重候选文本数量；进入 `ready` 后释放工作簿。
3. 用户确认开始后重新打开输入文件。每个单元格先检查公式，再读取值；逐个扫描全部工作表并收集目标单元格及其位置，绝不把公式的缓存字符串当成普通文字覆盖。
4. 对标准化后的原文去重。同一文本不论出现在哪个工作表，只请求一次所需语言的翻译，再映射回所有单元格。
5. 按受控批次调用翻译服务，串行批次更新进度。每批设置超时并最多重试两次，采用短暂递增退避。
6. 普通字符串只改写单元格值；富文本只追加新的翻译片段并保留原片段。两者都不设置单元格样式、不移动单元格、不增删行列、不修改工作表名称或可见性。
7. 把结果写到同一工作簿对象，再以与输入相同的 OOXML 类型输出到新的临时文件。
8. 重新打开输出文件并执行结构与关键部件校验，通过后才允许下载。

翻译服务只接收去重后的文字，不接收完整 Excel 文件、公式、图片或格式。由于当前 `google-translate-api-x` 依赖非正式的 Google Translate 访问方式，服务层必须与具体供应商隔离，便于以后切换到带 API Key 的正式服务。

## 格式、图片和宏的保真边界

`xlsx-populate` 的用途是修改现有 OOXML 单元格并尽量保留未操作的工作簿内容，但任何第三方库都不能仅凭“输出成功”证明复杂工作簿完全无损。因此下载前增加两类保护：

1. 结构校验：输出必须可被重新打开；工作表数量、名称、顺序和可见性，合并区域集合，行高、列宽，定义名称，公式文本、公式类型与引用范围，以及所有单元格的样式引用必须与输入一致。除处理阶段记录的目标单元格外，其他单元格值不得变化。
2. 包部件校验：对 `xl/media/`、`xl/drawings/`、`xl/charts/`、`xl/externalLinks/`、`xl/pivotTables/`、`xl/pivotCache/`、`xl/embeddings/`、`xl/activeX/`、`xl/ctrlProps/`、`customXml/`、对应 `.rels` 和 VBA 相关部件，输入输出的路径集合及每个部件解压后内容的 SHA-256 必须完全一致；不比较 ZIP 压缩方式或时间戳。

`.xlsm` 必须保留原扩展名和宏启用 Content-Type。若输入含 `xl/vbaProject.bin`、VBA 签名或相关关系，输出中的对应二进制内容必须逐字节一致；任何宏校验失败都会把任务标记为 `failed`，不提供可能损坏的文件下载。`.xlsm` 支持必须通过下述带宏样本的上线闸门后才能启用，不能仅凭库调用成功就开放。首版不承诺翻译受密码保护、加密或损坏的工作簿，这些文件在预检阶段直接拒绝。

## 失败与恢复

- 单个文本经过两次重试仍失败：保留该单元格原值，记录失败计数，继续其他内容，最终状态为 `completed_with_warnings`。
- 存在待翻译文本，但翻译服务从任务开始即完全不可用，或没有任何待翻译文本成功：任务标记为 `failed`，不生成伪成功文件。
- 写文件、重新打开或完整性校验失败：删除输出，任务标记为 `failed`，原上传文件在过期清理前保留以便日志排查，但不允许下载。
- 超过 Excel 单元格文字长度上限的拼接结果：该单元格保持原值并计为失败。
- 页面轮询遇到短暂网络错误：保留当前进度并重试查询，不重复创建翻译任务。
- 任务到期后删除状态及文件，后续查询返回 `404` 并提示重新上传。服务器重启导致任务丢失时采用同一提示；临时目录在启动时清理。

日志只记录任务 ID、用户 ID、文件名、数量、耗时、状态和技术错误，不记录完整单元格内容。审计日志可记录任务开始和下载动作，但不得把翻译任务加入产品/走货数据。

## 测试与验收

### 自动化测试

- 语言分类：中文、英文、印尼文、混合文本、已有双语/三语、代码和应跳过内容
- 幂等性：系统生成的双语/三语内容再次处理不重复追加
- 去重与映射：跨工作表重复文本只请求一次并正确回填全部位置
- 翻译提供方：批次顺序、超时、两次重试、部分失败和完全失败，测试中使用假实现，不依赖外网
- 工作簿：多工作表、隐藏工作表、公式、日期、合并区域和格式化单元格只修改目标文字值
- 富文本：原片段文字和样式不变，只追加一次翻译片段，二次处理不重复追加
- 完整性：关键 OOXML 部件缺失或宏二进制变化时拒绝下载
- API：未登录、错误类型、超限文件、任务所有权、状态迁移、下载门槛和过期清理
- 前端：lint 与生产构建通过，任务状态到按钮/进度/警告的映射正确

### 实际文件验收

使用用户提供的 29 个工作表文件进行端到端验收：

- 29 个工作表全部被扫描，工作表名称、顺序和可见性不变
- 中文、英文和印尼文按规则补齐；型号和公式未被误改
- 视觉抽查确认格式、富文本、图片位置与尺寸、合并单元格均无变化，公式表达式完整保留
- 文件含公式时展示“阅读型副本”提示；允许 Excel 重算后依赖已翻译文字的结果发生变化
- 输出文件可在 Microsoft Excel 中直接打开，不出现“发现不可读取的内容”或修复提示
- 输出文件再次上传后不重复追加翻译
- 在已有部分文字翻译成功后模拟后续请求失败，能显示失败数量并下载保留失败单元格原文的部分成功文件；若全程没有任何翻译成功则不得下载

另使用带 VBA 宏和图片/图表的专用 `.xlsm` 样本验证：输出扩展名、宏二进制、宏启用 Content-Type、图片和图表部件保持一致，并在 Excel 中打开及运行宏进行人工确认。

## 非目标

- 不翻译工作表名称、公式、批注、文本框、图表标题、图片内文字或 VBA 代码。
- 不提供人工逐格校对、术语库管理或翻译记忆库持久化。
- 不把翻译结果同步到现有走货明细、产品、核价或 A-DOC 数据。
- 不支持 `.xls`、`.xlsb`、CSV、加密文件或在线协同编辑。
- 不在首版接入需要付费 API Key 的 OpenAI、Google Cloud Translation 或 DeepL；供应商封装为以后切换保留接口。
