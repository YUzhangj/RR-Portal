# 同模机台批量同步设计

## 目标

当用户在排机明细中手动修改某条记录的机台号时，如果当前排单内还有“模号名称完全相同”的记录，系统先提示受影响条数；用户确认后，把这些同模记录一起移动到目标机台。

## 范围与规则

- “同一套模”按 `mold_name`（模号名称）完全相等判断。
- 同步范围仅限当前 `schedule_id` 对应的排单，不影响其他日期、班次或排单。
- 只同步 `machine_no`（机台号）；产品货号、颜色、料型、啤重、用料等字段保持原值。
- 同模记录只有当前一条时，直接保存，不显示批量确认。
- 同模记录有两条或以上时，显示确认框：“同模共 N 条，将一起移到 XX 机台，是否确认？”
- 用户取消确认时，本次修改不保存。

## 前端交互

排机明细现有两种机台修改入口都使用相同规则：

1. 点击蓝色机台号进行快速切换。
2. 点击“编辑”，修改机台后点击“保存”。

前端根据当前已加载的明细，以 `mold_name` 完全相等统计同模条数。需要批量同步时弹出确认框；确认后在更新请求中显式发送 `sync_same_mold_machine: true`。

保存成功后重新加载当前排单明细：

- 批量同步时提示“已将同模 N 条排机记录移动到 XX 机台”。
- 单条修改时保留现有的成功提示。

## 后端处理

继续使用现有接口：

`PUT /api/scheduling/:id/items/:itemId`

后端先按 `itemId` 和路由中的 `schedule_id` 查找当前记录，避免修改到不属于当前排单的数据。

仅当以下条件同时满足时批量同步：

- 请求包含 `sync_same_mold_machine: true`；
- 请求包含 `machine_no`；
- 新机台号与数据库中当前机台号不同；
- 当前记录的 `mold_name` 非空。

满足条件时，在同一个数据库事务中：

1. 保存当前记录的其他编辑字段。
2. 将当前排单内 `mold_name` 完全相同的全部记录更新为目标机台。
3. 保持现有“人工改机台后学习模具到机台映射”的行为。

接口响应增加 `synced_same_mold_count`，表示本次同步的同模记录总数（包含当前记录）。未触发批量同步时返回 `1`。

## 异常与边界

- 记录不存在或不属于路由指定的排单时返回 404。
- 没有可更新字段时仍返回 400。
- 编辑其他字段但机台号未改变时，即使表单携带 `machine_no`，也不批量覆盖同模记录。
- 空模号名称不会作为同模分组依据。
- 批量同步不跨排单，避免历史排单和其他班次被意外修改。

## 验证

后端自动化测试覆盖：

1. 当前排单内同模记录一起改机台，不同模记录保持不变。
2. 另一排单中同名模具不受影响。
3. 编辑其他字段且机台未改变时，不覆盖同模记录原有机台。
4. 非法的排单与明细组合返回 404。

前端通过浏览器验证：

1. 快速切换机台时出现正确的同模条数和目标机台提示。
2. 取消后数据不变，确认后同模记录同时更新。
3. “编辑”表单修改机台时采用相同确认和同步逻辑。
4. 修改非机台字段不会触发同模确认。
