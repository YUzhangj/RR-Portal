# 修复期间暂停操作

修改或部署前，在品质系统运行环境中使用同一个 `DATA_PATH` 开启维护：

```sh
npm run maintenance:on
npm run maintenance:status
```

命令在数据目录创建 `maintenance.lock`。后台逐请求检查并返回 503，
页面每 5 秒检查一次并显示“系统修复中”；已打开的旧页面即使继续提交，也无法写入服务器。
请求读取完正文后也会重新检查，避免维护开启期间仍落入写入流程。
数据、当前页面内容和未同步草稿不会被清理，不会自动重发。

验证完成后关闭维护：

```sh
npm run maintenance:off
```

页面显示“修复已完成”，提示先核对未保存内容，再点击“刷新后继续”。
不会自动刷新并丢弃表单。全程使用独立健康接口 `/api/health`；
维护状态接口 `/api/maintenance` 仅返回状态，不返回业务数据。

也可设置 `QC_MAINTENANCE=1` 启动；这种方式需清除环境变量并重启才能解除。
正常部署默认关闭维护；维护标记留在数据目录，不随版本或 PR 发布到生产。
