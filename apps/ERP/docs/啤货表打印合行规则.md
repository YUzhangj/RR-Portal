# 啤货表打印合行规则(2026-10-08 定)

## 已落地的过渡规则(无需排模表,代码已生效)

打印啤机部生产啤货表时,满足以下**全部**条件的明细行合并为一行:

1. **同一工模编号**(塑胶物料资料.工模编号)
2. **同一色粉号**(色粉号为空时按颜色)——换色再啤的不合,一色一行
3. **同一用料名称**
4. 物料名称形如 **左X / 右X**(前缀配对)

合并后:

- 行名 = 去左右前缀(左耳朵+右耳朵 → 耳朵)
- 数量 = 组内最大(对数;正常左右相等)
- 整啤净重 = 组内最大(**不合计**)——物料资料里整啤净重按整套模登记,对件共享同值(如耳朵模 181.5G)
- 啤数 = ⌈合并数量/出模数⌉,总净重KG = 整啤净重×啤数/1000
- 用料汇总按合并后行算(此前按单件行算会虚增一倍)

代码:`web2/src/lib/plasticPurchase.ts` 的 `mergeMoldPairLines`,`buildMoldingSheetHtml` 首步调用。
非左右命名的件(大角/猫公仔等)一律不合行,原样逐行打印。

## 正式方案(待排模表功能)

老系统啤货表的「一色一行+工模名称」来自工程**排模表**:一套模出哪几件、每啤几套、
通用工模名称(配件模具/锁头)、配色安排,全是排模表的内容。后续做「工程排模表」模块后:

1. 排模表行 = 工模编号 + 色粉 + 工模名称 + 每啤套数 + 包含件
2. 啤货表打印直接按排模表出行,替换本过渡规则
3. 采购下单的同模分组(MoldGroupPanel)、堵模校验也可同源

在此之前,新下采购单遇到「铲子+猫砂盆」这类非左右命名的同模件,打印会保持逐件分行
(数量/啤数/净重各自正确,只是没有合并行名),不影响订料与发料计算。
