# P7d 工资表生成（公式引擎）设计

> 兴信B ERP 净室重建 · P7 算薪(M10)第四切片 · **P7 收官** · 2026-06-08

**目标**：按 月份+部门+模板 生成工资表——快照模板公式到 `工资表项目公式`（分配 ZGnn 列名），逐员工用**手写公式引擎**求值各台头项目（引用 基本工资/计件工资/出勤/前序项），写 `工资明细表`（动态 ZG 列）+ 汇总 `工资总表`。整合 P7a 计件归集 + P7b 出勤 + P7c 模板公式。

**已确认决策（与用户）**：
- 公式引擎 = **手写简易求值器**（无第三方依赖）：+ − * / ( )、十进制字面量、变量（台头项目/内置）。
- 求值**按序号顺序**：公式只能引用**排在前面的台头项目 + 内置变量**（无需拓扑排序）。
- **不做审核**：生成 = 实时计算写入；**可重算**（按 月份+部门 删旧重建）。零改表（不动工资总表审核列、不入白名单）。
- 合计（草案）：**类型驱动**——应发合计=Σ类型'应发'项、应扣合计=Σ类型'应扣'项、实发合计=应发合计−应扣合计（三个标准列引擎算；合计-type 项仅计算存列不参与标准合计）。
- 内置变量（草案）：基本工资(人事档案)、计件工资(P7a计件归集)、应出勤天数(生成入参)、实出勤天数(应出勤−缺勤)、缺勤天数(P7b出勤)。
- 成本保密（草案）：「工资表」**打开权限即看金额**（薪资敏感由 HR 专属菜单授权控制，不逐列脱敏）。

---

## 1. 数据模型 — 零改表

- `工资总表`(头)：工资表编号 nvarchar(30)/月份/部门编号/模板编号/开始日期/结束日期/审核/操作员/基本工资/计件工资/应发合计/应扣合计/实发合计。
- `工资明细表`：工资表编号/月份/编号/姓名/部门编号/部门/职称/基本工资/计件工资/应发合计/应扣合计/实发合计 + **动态项列 ZG01..ZG46**（最多 46 个工资项，超则报错）。全 decimal(18,4)。
- `工资表项目公式`：工资表编号/月份/部门编号/台头项目/类型/公式/**列名**(=ZGnn) —— 模板公式在该工资表的快照 + 列名映射。
- 人事档案.基本工资 = decimal(18,4)。
- **无新建/ALTER 脚本**（工资总表审核列不用，无审核）。

## 2. 公式引擎（`src/ErpApi/Features/Payroll/FormulaEvaluator.cs`，纯函数无 DB）

`static decimal Evaluate(string formula, IReadOnlyDictionary<string, decimal> vars)`：
- 递归下降：`expr = term (('+'|'-') term)*`；`term = factor (('*'|'/') factor)*`；`factor = number | identifier | '(' expr ')' | '-' factor`。
- token：数字（`[0-9]+(.[0-9]+)?`）、运算符 `+ - * / ( )`、标识符（连续的非运算符/非括号/非空白字符——支持中文台头项目名如 `基本工资`）。
- 标识符 → `vars[name]`；未知变量 → 抛 `FormulaException("未知变量: X")`。除零 → 抛 `FormulaException("除以零")`。空公式 → 返回 0。
- 单测覆盖：四则/括号/优先级/一元负/变量/未知变量/除零/中文变量名。

## 3. 生成服务（`PayrollService.GenerateAsync(月份, 部门编号, 模板编号, 应出勤天数, user)`）

复用 P7a `PieceworkPayrollService`、P7b `AttendanceService`、P7c 模板（直接查 工资模板项目+公式 或复用 WageTemplateService.GetAsync）。事务内：
1. 校验 月份(yyyyMM)/部门/模板；载入模板项目（序号顺序，含 台头项目/类型/公式）；项数>46 → ArgumentException。
2. **可重算**：`DELETE 工资明细表 / 工资总表 / 工资表项目公式 WHERE 月份=@月份 AND 部门编号=@部门编号`（清旧）。
3. 工资表编号 = docNo（前缀 `GZ`+yyyyMMdd+流水）或 `月份+部门编号`（取 docNo，记录于头）。
4. 快照模板 → `工资表项目公式`：逐项（序号 i 从1）列名=`ZG{i:00}`，插入(工资表编号/月份/部门编号/台头项目/类型/公式/列名)。
5. 取该部门**在职**员工（人事档案 在职'1' AND 部门编号=@）：对每人
   - 内置变量：基本工资=人事.基本工资；计件工资=P7a 该员工当月计件归集Σ金额；应出勤天数=入参；缺勤天数=P7b 该员工当月Σ缺勤(TRY_CONVERT)；实出勤天数=应出勤−缺勤。
   - 逐项（序号顺序）`值=FormulaEvaluator.Evaluate(公式, vars)`；`vars[台头项目]=值`；记入 ZGnn。
   - 应发合计=Σ(类型'应发'项值)；应扣合计=Σ(类型'应扣'项值)；实发合计=应发合计−应扣合计。
   - 插入 `工资明细表`（编号/姓名/部门/职称/基本工资/计件工资/应发合计/应扣合计/实发合计 + 各 ZGnn）——**动态列**：按本工资表的 列名集合 拼 INSERT 列（ZGnn 为内部生成名，非用户输入，安全）。
6. 插入 `工资总表`（工资表编号/月份/部门/模板/开始结束日期[月初/月末]/审核'0'/Σ基本工资/Σ计件工资/Σ应发合计/Σ应扣合计/Σ实发合计）。
- 公式错误（未知变量/除零）→ FormulaException → 控制器 400「公式错误: …」（整批失败，用户修模板重算）。

## 4. 查询服务 + 控制器

- `PayrollQueryService`：`ListAsync(月份?, 部门编号?)`→工资总表列表；`GetDetailAsync(工资表编号)`→{ 头, 项目:[{列名,台头项目,类型}](来自工资表项目公式,序号序), 明细:[工资明细表行(编号/姓名/.../ZG01..ZGnn/合计)] }。
- `PayrollController`（`api/payroll/wages`）：`POST generate {月份,部门编号,模板编号,应出勤天数}`(功能权限,409/400 on 公式错误/校验)、`GET`(list,打开)、`GET {工资表编号}`(detail,打开)、`DELETE {工资表编号}`(反生成,删除权限,删三表 by 月份+部门 或 工资表编号)。Menu `工资表`。**打开权限即看金额**(不脱敏)。DI 注册两服务 + FormulaEvaluator(静态无需DI)。
- 权限种子 `db/seed_p7d_perms.sql`：admin 工资表(打开/删除/打印/金额/功能)。

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 公式引擎健壮性 | 手写递归下降 + 充分单测（优先级/括号/一元负/中文变量/错误）；未知变量/除零抛 FormulaException→400。 |
| 求值顺序 | 按序号；公式只引用前序项+内置（文档/前端标注）；引用后项=未知变量报错。 |
| 动态 ZG 列 | 列名 ZG{序号:00} 内部生成（非用户输入）→ 拼 INSERT 安全；项数 cap 46。 |
| 重算重复 | 生成前按 月份+部门 删三表再建（事务）。 |
| 合计口径 | 类型驱动（Σ应发/Σ应扣/差）；基本工资/计件工资作内置值也可作应发项参与合计（看模板）。 |
| 薪资敏感 | 「工资表」菜单打开权限即授权看金额（HR 专属）；本期不逐列脱敏，靠菜单授权。 |
| 计件/出勤口径一致 | 复用 P7a PieceworkPayrollService / P7b AttendanceService（同 月份/在职/审核口径）。 |
