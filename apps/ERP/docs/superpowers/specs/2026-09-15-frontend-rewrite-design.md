## 背景与动机

老前端（web/，React+antd）经多轮迭代后用户反馈三类问题：

- **视觉太老**：配色/字体/间距/布局陈旧
- **操作不顺**：菜单层级绕、单据说切就切丢数据、常用操作步骤多
- **性能不好**：大表格卡顿、切页重复拉数据

用户授权"大变都行，只要和后端联动就行"，并明确**技术栈可换**。

## 已确认的关键决策

| 决策点 | 结论 |
|---|---|

| 技术栈 | React 19 + Vite + TypeScript + Tailwind 4 + shadcn/ui + TanStack Query/Table + react-hook-form + zod |

| 数据库 | 零改动 |

| 首批范围 | 登录页 + 主框架 + 10 个核心页（见下） |
| 备份 | git 提交 5bd9114 + erp 库快照 db/snapshot/pre-redesign-20260915/ + 桌面整份复制 New-Process-old-20260915/ |

## 工程与部署

- 新工程目录 `web2/`（独立 Vite 工程，与 web/ 互不引用）
- 开发：`web2/` 跑 5174，老系统 5173，后端 5000 共用
- 生产：构建产物静态托管（/new 路径或独立端口），老系统不下线
- API 层：按 `web/src/api/*` 的 URL/参数/中文字段名逐个提炼为类型安全封装（fetch + zod 校验），不做任何后端适配层改动

## 视觉体系

- 浅色现代 SaaS 风（参考飞书/Linear 的干净感）：一个主色 + 灰阶 + 语义色（成功/警告/危险/信息）
- 4pt 间距网格、字号阶梯、统一圆角与阴影、中文字体栈优化
- 表格密度三档（紧凑/标准/宽松）用户可切，记住选择
- 登录页全新设计
- 不做暗色模式、不做花哨动效

## 应用外壳

- 左侧可折叠分组导航（沿用现有分组名：工程部/装配部/来料仓/塑胶仓/船务部/业务部…）
- **标签页多开**：单据页以标签形式并存（如同时开着"生产通知单 SC20260915003"和"来料领料单"），切换不丢编辑状态；记住上次打开的标签
- Ctrl+K 全局搜索：搜菜单、搜单号直达
- 顶栏：消息中心入口、审核待办、用户菜单
- 每页右上角"回旧版"链接（跳老系统对应页）

## 单据页统一骨架

- 顶部操作栏：新建/打开/保存/保存修改/删除/审核/反审核/打印…按权限显隐
- 单头卡片：字段分组，次要字段可折叠
- 明细表格：TanStack Table 虚拟滚动、行内编辑、键盘导航、Excel 多行粘贴
- 三级流转（主管审核→经理审核→审核/出库）可视化状态条，当前步骤一眼可见
- 业务规则逐条移植：权限脱敏（单价/金额）、带入锁定（如补料锁生产单号）、BOM-PO 绑定确认等——以老系统测试场景为核对清单

## 性能

- 路由级代码分割，首屏只载框架
- TanStack Query 接口缓存与去重，切页不重复拉取
- 表格虚拟滚动（万行明细不卡）
- 物料/款号等大下拉改远程搜索分页

## 明确不做（YAGNI）

- 后端/数据库任何改动
- 移动端适配（桌面优先）
- 暗色模式
- 外部系统（RR-Portal/排产/喷油等）入口重做（保留跳转链接）
- 老系统删除（长期保留可回退）

## 风险与对策

| 风险 | 对策 |
|---|---|
| 业务细节遗漏（带入/锁定/脱敏） | 以老系统 vitest 场景为核对清单逐条移植；新旧对照验收 |
