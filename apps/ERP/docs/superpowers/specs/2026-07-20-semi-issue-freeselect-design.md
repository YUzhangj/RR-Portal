# 半成品出库单（自由选产品版）设计文档

**日期**：2026-07-20
**分支**：`codex/semi-finished-label-order`
**状态**：设计已确认，待写实现计划

## 背景

原系统「半成品出库单」界面 + 「资料」产品选择器（原料资料查询MZFAD）两张截图。本系统 `半成品出库单` 已存在但为**旧的列表+抽屉极简形态**（菜单 `半成品出库单` → 路由 `/semi-issues` → 权限菜单 `半成品领料`，后端 `SemiIssue` 已建，库存 union 已含 `半成品领料明细单 数量*-1`），远不匹配截图。本次**按截图重写**为全屏领料式主从单 + 自由选产品，与刚交付的「半成品退仓单（自由选产品版）」高度同构。

## 目标

把半成品出库单从「物料编号行」极简录入改成截图的「自由选产品」模型：领料式头（部门/领料人/拉长/收件人/领料备注/件数/卡板数/制单人…）→ 点「资料」从产品库自由选产品录出库数量 → 审核实时减半成品库存。

## 与半成品退仓单的异同

| 维度 | 半成品退仓单（已交付） | 半成品出库单（本单） |
|---|---|---|
| 表 | 半成品退仓单/明细单 | **半成品领料单/明细单**（复用） |
| 方向 | 减（union 已含） | 减（union 已含 `半成品领料明细单*-1`） |
| 头样式 | 供应商头（入仓单号带出供应商/仓库） | **领料式头**（部门/领料人/拉长/收件人/领料备注/件数/卡板数/制单人） |
| 仓库来源 | 入仓单号带出 | **固定 `半成品仓`**（截图头无仓库字段） |
| 入仓单号 | 必选 | **无**（出库不绑定具体入仓单） |
| 价格 | 有价（金额=Σ数量×库存单价，按单价权限脱敏） | **无价**（截图明细无单价/金额列，底部仅数量合计） |
| 审核 | 自定义 SetApproved（翻位） | **复用 PostingEngine**（已在 PostableDocuments 白名单，翻位+写审核日期，union 减） |
| 资料自由选 | SemiFinishedLabelProductPicker | 同一 picker（`permissionMenu="半成品领料"`） |
| 右侧库存参考 | 无 | **有**（序号/配件编号/产品装配名称/发料数量/库存数量） |

## 关键决策（用户已拍板）

1. **装配采购清单调入按钮 → 缓做**：v1 专注「资料」自由选产品；装配采购清单按钮**占位禁用**，后续再接调入源。
2. **右侧库存参考网格 → 建**：只读展示已选产品当前库存，前端拉 `/api/semi-inventory?仓库=半成品仓` 按 `物料编号` 映射，`发料数量`=明细行数量、`库存数量`=当前实时库存。零新增后端。
3. **额外领料头字段 → 加列全建**：幂等 ALTER 给 `半成品领料单` 补 `拉长/收件人/领料备注/件数/卡板数/制单人` 六列（`审核日期` 已存在）。
4. **仓库来源 → 固定 `半成品仓`**：截图头无仓库选择，默认唯一半成品仓。**实现细节**：DTO 保留 `仓库` 字段，前端硬编码发 `半成品仓`（无 picker），服务端 `空→默认 半成品仓`；这样既对用户"固定"、又保持可测（DB/集成测试可传 `P5c半成品仓` 复用现有 P5c fixture）。

## 架构

- 复用 `半成品领料单/半成品领料明细单` 两表；仅新增头 6 列（幂等 ALTER，纯增不破坏现有极简调用）。
- ASP.NET Core 控制器保留权限/月结锁/日志/**PostingEngine 审核**；Dapper 服务改为自由选产品：保存时**仓库固定 `半成品仓`**，按 `物料编号 + 仓库` 从最近已审核 `半成品入仓明细单` 派生权威 `颜色/规格/单位/单价/生产单号`（保证实时库存 union 按 仓库+物料编号+颜色 正确净额）。
- React 页面全屏主从，替换旧 `SemiIssuePage`(列表)+`SemiIssueCreateDrawer`；明细来源换成复用退仓的 `products` 自由选择器；右侧加库存参考网格。

## 技术栈

SQL Server migration（幂等 ALTER）、ASP.NET Core 8、Dapper、xUnit、React 19、TypeScript、Ant Design 6、Vitest。

## 数据模型

### DB 迁移（幂等 ALTER，`半成品领料单` 加列）
`拉长` nvarchar(20) / `收件人` nvarchar(20) / `领料备注` nvarchar(40) / `件数` decimal(18,4) / `卡板数` decimal(18,4) / `制单人` nvarchar(20)。均可空。`审核日期` 已存在不加。

### 明细列映射（自由选产品字段 → 现有 `半成品领料明细单` 列）
- 配件编号 → `物料编号`
- 产品装配名称 → `物料名称`
- 产品货号 → `货号`
- 产品名称 → `名称`
- 客户 → `客户`
- 生产单号 → `生产单号`
- 数量 → `数量`
- 备注 → `备注`
- 颜色/规格/单位/单价 → 由 ReceiptFacts 派生落库
- 金额 → 数量×单价（内部记录，不显示）

## 组件与数据流

### 后端 Service（`SemiIssueService` 重写）
- `SaveCoreAsync`（自由选产品）：
  - 校验：至少一行、配件编号必填、数量>0、同单配件编号不重复。
  - 仓库固定 `半成品仓`。
  - 每行按 `物料编号 + 半成品仓` 从最近已审核 `半成品入仓明细单` 派生 `ReceiptFacts`（颜色/规格/单位/单价/生产单号/货号/名称/客户）。
  - 落库头（新字段）+ 明细（仓库/物料编号/颜色/数量 必落）。
- `ProductsAsync`：与退仓同一 CTE（`款号物料总表`→自由选产品，OUTER APPLY 取生产单号），保留 `canSeePrice` 脱敏参（由 `半成品领料` 单价权限驱动，无权限置 null）。**前端出库页不渲染价格列**（无价单），故即便有权限也不显示；脱敏参仅防端点被直接调用时泄露。
- `GetAdjacentAsync`：前单/后单（镜像退仓）。
- 保留 `List/Get/Delete`。
- **审核不改**：Controller 继续 `posting.ApproveAsync/UnapproveAsync`（PostingEngine 翻位+审核日期，union 减库存）。

### 后端 Controller（`SemiIssueController`）
- 新增 `GET products`、`GET {no}/adjacent`。
- `approve/unapprove` 保持走 posting，不动。

### 前端
- `api/semi.ts`：重写 `SI*` 类型（自由选产品）+ api（products/adjacent）。
- `utils/semiIssue.ts`：`mergeSemiIssueLines`（按配件编号去重）/`validateSemiIssue`（仓库固定故只校验明细：至少一行、数量>0、配件编号不重复）。纯计算 + vitest。
- `pages/warehouse/SemiIssuePage.tsx`：全屏主从重写（删 `SemiIssueCreateDrawer`）：
  - 工具栏：新建/打开/保存/删除/**装配采购清单（禁用占位）**/刷新/资料/前单/后单/审核/反审核/表格设置（禁用）/打印/关闭。
  - 头：部门/日期/审核日期（只读）/领料人🔍/拉长🔍/收件人🔍/领料备注（下拉）/电脑单号（只读）/备注/操作员（只读）/件数/卡板数/制单人🔍。审核状态 Tag。
  - 明细列：删除/装配采购（**空占位**）/配件编号/客户/产品货号/产品名称/产品装配名称/生产单号/数量（录入）/备注。
  - 右侧库存参考网格：序号/配件编号/产品装配名称/发料数量（=行数量）/库存数量（拉 `/api/semi-inventory?仓库=半成品仓` 按物料编号映射）。
  - 底部：**仅数量合计**（无金额）。
  - 资料复用 `SemiFinishedLabelProductPicker`（`permissionMenu="半成品领料"`）；领料人/拉长/收件人/制单人用 `EmployeePicker`。

## 错误处理

- 保存校验失败 → `ArgumentException` → 400 `{消息}`。
- 月结锁 → PeriodLockService（保留现有）。
- 审核经 PostingEngine，失败返回现有语义。
