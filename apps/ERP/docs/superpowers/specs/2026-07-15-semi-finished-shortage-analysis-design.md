# 半成品欠料分析表设计

## 目标

在“半成品仓库”菜单下实现“半成品欠料分析表”，用于识别已审核且尚未完成的生产制单中，当前半成品库存不足的产品。页面沿用本项目现有的现代 ERP 布局、筛选栏、数据表格和权限控制，不复刻旧 Windows 窗口样式。

## 范围

- 新增菜单：`半成品仓库 / 半成品欠料分析表`。
- 新增前端路由：`/semi-finished-shortage-analysis`。
- 新增后端查询与导出接口，欠料结果由后端实时聚合。
- 支持普通查询、精确查询、分页、表格设置、Excel 导出、打印和关闭。
- 本功能只提供查询分析，不新增库存单据，也不修改生产制单或库存流水。

## 数据口径

### 需求数量

需求来源为生产制单：

- 只统计已审核的生产制单。
- 只统计未完成的生产制单。
- 按客户和产品货号汇总计划数量。
- 产品名称取生产制单对应的产品/款式名称。

同一客户、同一产品货号存在多张符合条件的生产制单时，需求数量为计划数量之和。

### 半成品映射

产品货号通过现有半成品共用物料/装配资料映射到：

- 配件编号
- 产品装配名称
- 单位

只统计配置了配件编号的有效映射。没有配件编号的产品不进入欠料结果，避免生成无法对应库存的无效行。

### 库存数量

库存数量使用现有半成品库存引擎的统一口径：

- 已审核的半成品入仓增加库存。
- 已审核的半成品领料/出仓减少库存。
- 已审核的半成品盘点盈亏调整库存。
- 按配件编号汇总全部半成品仓库的当前库存。

本页面不提供仓库筛选。库存始终为全部半成品仓库合计，不能误用单一仓库的库存数。

### 欠料数量

计算公式：

```text
欠料数量 = max(需求数量 - 库存数量, 0)
```

默认且固定只返回欠料数量大于 0 的记录。库存大于或等于需求时，该记录不显示。

## 后端设计

新增独立的半成品欠料分析功能目录，保持控制器、DTO、服务和数据聚合职责分离。

### 查询接口

接口约定：

```text
GET /api/semi-finished-shortage-analysis
```

查询参数：

- `field`：`productCode`、`productName`、`customer`、`partCode`
- `keyword`：查询值
- `exact`：是否精确匹配
- `page`：页码
- `pageSize`：每页条数

响应包含：

- `items`
- `total`
- `page`
- `pageSize`

每行字段：

- `customer`
- `productCode`
- `productName`
- `partCode`
- `assemblyName`
- `unit`
- `requiredQuantity`
- `inventoryQuantity`
- `shortageQuantity`

服务端先聚合需求，再关联半成品映射和全部仓库库存，计算欠料后过滤 `shortageQuantity > 0`，最后应用查询条件、稳定排序和分页。默认排序为客户、产品货号、配件编号升序。

### 导出接口

接口约定：

```text
GET /api/semi-finished-shortage-analysis/export
```

导出使用与列表完全相同的筛选、数据口径和排序，不受当前分页限制。Excel 列顺序与页面表格一致。

### 权限

功能使用独立权限点：

- 打开页面
- 导出 Excel
- 打印

无打开权限时菜单和路由均不可访问。无导出或打印权限时对应按钮禁用或隐藏，并由后端再次校验导出权限。

## 前端设计

页面使用项目内现有报表页结构，与其他现代 ERP 页面统一：

- 页面标题：半成品欠料分析表
- 顶部操作区：记录数、表格设置、导出 Excel、打印、关闭
- 查询区：查询字段、关键字、查询、精确查询
- 主体：可横向滚动的数据表格
- 空状态：保留表头并显示统一空数据提示

查询字段选项：

- 产品货号
- 产品名称
- 客户
- 配件编号

表格列顺序：

1. 客户
2. 产品货号
3. 产品名称
4. 配件编号
5. 产品装配名称
6. 单位
7. 需求数量
8. 库存数量
9. 欠料数量

数量列右对齐，并使用项目统一的数量格式。欠料数量作为关键结果列保持可见且视觉强调适度，不使用旧系统的高饱和文字配色。

普通查询使用包含匹配；精确查询使用完全匹配。查询条件、页码和表格列设置遵循现有报表页交互模式。

## 错误与边界处理

- 生产制单缺少产品货号时忽略该记录。
- 产品没有有效配件编号时忽略该记录。
- 没有库存流水时库存数量按 0 处理。
- 需求或库存聚合出现空值时按 0 处理。
- 接口失败时使用项目统一错误提示，并保留当前查询条件。
- 导出失败不得生成空文件，应显示明确错误提示。
- 所有数量计算使用十进制类型，避免浮点误差。

## 测试策略

### 后端

- 只纳入已审核且未完成的生产制单。
- 同客户同货号的需求正确汇总。
- 全部半成品仓库的入仓、出仓和盘点正确合并。
- 无库存时按 0 计算。
- 库存等于或大于需求时不返回。
- 欠料数量严格等于需求减库存。
- 无配件编号映射时不返回。
- 普通查询和精确查询覆盖四个查询字段。
- 分页、总数和稳定排序正确。
- 导出与列表筛选结果一致。
- 页面、导出权限均被后端校验。

### 前端

- 菜单位于半成品仓库分组并跳转到正确路由。
- 页面标题、筛选字段、按钮和表格列完整。
- 查询与精确查询发送正确参数。
- 表格正确显示需求、库存和欠料数量。
- 无权限时菜单、路由和操作按钮行为正确。
- 空数据、接口错误、分页、导出和打印交互正确。

## 验收标准

- 页面视觉与本项目其他已统一的 ERP 报表一致。
- 默认只显示真实欠料记录。
- 任一行满足 `欠料数量 = 需求数量 - 全部半成品仓库库存数量`，且结果大于 0。
- 数据源限定为已审核、未完成的生产制单。
- 查询、精确查询、分页、导出、打印、关闭及权限控制可用。
- 前后端自动化测试和构建通过。
