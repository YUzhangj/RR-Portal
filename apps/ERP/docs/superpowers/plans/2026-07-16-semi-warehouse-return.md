# 半成品退仓单实现计划

**目标：** 在“半成品仓库”中新增独立的半成品退仓单，沿用现有现代前端样式，并确保退仓数量不能超过原入仓单的可退数量。

## 业务规则

- 新建退仓单时必须先选择一张已审核的半成品入仓单。
- 供应商、仓库和可选产品均从原入仓单带出，不允许跨入仓单选择产品。
- 每条退仓明细保存和审核时都重新校验：本次退仓数量 + 其他已审核退仓数量不得超过原入仓数量。
- 只有已审核的退仓单扣减半成品库存；反审核后恢复库存。
- 已审核单据不可修改或删除。

## 实现步骤

1. 新增前端业务规则测试，覆盖原单必选、明细必填、超可退数量和产品合并。
2. 新增 SQL 迁移，创建半成品退仓单头、明细及必要索引和权限。
3. 新增后端 DTO、Service、Controller、依赖注入和过账配置。
4. 在保存与审核事务中锁定原入仓明细并校验累计可退数量。
5. 将已审核退仓数量纳入半成品实时库存和月结账本。
6. 新增统一 Ant Design 风格页面、原入仓单选择器、产品选择器和打开单据选择器。
7. 接入路由和“半成品仓库”菜单。
8. 运行前后端测试、构建、发布、数据库迁移并刷新隐藏服务。
