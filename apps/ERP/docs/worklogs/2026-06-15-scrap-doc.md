## 需求

用户一句话:**「报废单和退料单的功能是一样的」**。即照退料单模式做一张报废单。

## 需求澄清(brainstorm,3 项拍板)

1. **库存方向**:报废 = **减库存**(料废掉/销毁,从仓扣减,像领料 `数量×-1`)。用户确认「功能一样」是指**录入界面/操作一样**,不是连库存方向也照搬成「加」。
2. 表头部门/经手人字段命名:**报废部门 / 报废人**。
3. 单号前缀:**`BF`**(经核对现有前缀无冲突)。

## 关键事实(已核实)

- 报废单基础设施**完全不存在**(无表/后端/前端/权限),`menuTree.tsx:76` 仅无路由占位 `M("报废单")`。从零照退料单纵切克隆。
- 前端是**配置驱动的通用单据组件**(`MaterialDocPage/CreateDrawer/DetailDrawer/MaterialLineTable`),路由 `materials/:doc` 通配查 config → **加一条 config + 菜单路径即白嫖**退料单全套(录入/生产制单🔍/物料🔍/报废人选人/审核/复制单/打印),**零新前端组件**。
- 退料单参照点:`DocType/Menu/Table="退料单"`、`Prefix="TL"`、`口径="物料"`;库存引擎 `MaterialInventoryService.LedgerUnion` 退料(+)、领料/采购退仓(−);审核留痕列由 `03_p0_additions.sql` 循环补;DB 经 `db/run-db.ps1`(numbered migrations,至 13)。
