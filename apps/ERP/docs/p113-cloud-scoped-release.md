# P112/P113 云端定向同步

本次只同步船务入口、原料下单/领料流程及必需依赖。以 RR-Portal 的 ERP 现有代码为基线，保留 `/erp/` 路由和其他模块行为；不整包覆盖本地新版 ERP。

## 业务口径

- 船务部入口指向 VoyagePlex `/voyageplex/`。
- 新啤机采购单保存时冻结净用料来源，原料生产需求表据此显示需求。旧单保持原身份，不批量回填，不将旧手工需求单重新解释为新啤机需求。
- 采购按库存、需求及已有采购占用计算缺口。常用原料由资料页人工勾选；不常用原料最多比实际缺口额外 2 包。例如缺口 28 KG、每包 25 KG，最多采购 3 整包，4 包禁止保存和审核。
- 领料选择已审核的真实啤机来源，带出冻结数量。啤机主管、经理审核后发送原料仓待出库消息；仓管确认出库才扣库存，反审核恢复库存并重置审批阶段。
- 首笔新政策采购入仓与首次领料均保留原库存期初，避免首笔流水遗漏已有库存。新政策采购入仓缺少单位或包重时，仅从本单同原料一致的冻结来源补缺省；显式冲突值拒绝，历史 NULL 政策不回填。
- 新库存台账参与的盘点单，同一原料不允许重复明细，保存和最终审核均复核；保存、审核、反审核及删除均在事务中复核现行权限；旧台账盘点与反审核沿用原有规则。

## 账号配置

账号管理增加“原料流程岗位”。仅真实启用的 admin 且具备账号管理“打开／保存”权限可以配置岗位；普通账号管理用户只读，admin 本身不绑定普通岗位。岗位仅限定本流程职责，仍须具备原有菜单权限；保存、审核和最终过账在事务内复核权限、岗位、数量与库存。管理员同样受业务状态和库存限制。

迁移不猜测现有账号岗位、不新增人员、不授予菜单权限。可明确配置啤机文员、主管、经理、原料仓仓管和仓务经理；啤机经理可处理主管阶段。未配置有菜单打开及审核权限的原料仓仓管时，经理审核会阻止提交并提示管理员配置，避免通知丢失。

## 数据库与发布边界

本次仅执行固定哈希的 `173`、`174`、`175`。175 补齐旧云端所缺的原料快照、配方、期初和专属岗位结构，不运行全局部门岗位重建或历史回填。所有新增历史字段保持 NULL、新表保持空；原字段及记录保留。迁移工具的操作和验证契约见 `tools/ErpScopedMigration/README.md`。

发布由专用 ops 分支的 ERP-only 工作流完成。先旁路构建，保留现用环境/JWT、appsettings、上传挂载和旧静态资源；ERP 单独维护后做 SQL Server COPY_ONLY/CHECKSUM 备份和 VERIFYONLY，再执行单事务定向迁移并切换 API。SQL Server、nginx 和其他应用不重建。失败回退原 API，不恢复数据库覆盖用户活动。

**本次不得触发通用 `erp-db-init` 全目录重跑或 ERP Data Restore。** 旧初始化脚本含历史数据修复和权限种子，不能用来同步已正式录入的云端数据库。代码合并采用 `[skip ci]` 跳过通用 push 部署，业务回归和定向部署另有独立证据；后续 ERP 发布也须检查迁移范围与现存业务数据，不能直接沿用旧全量初始化流程。

验证结果和具体发布版本以本次最终工作记录及 Actions 为准；构建成功不等于业务链通过。
