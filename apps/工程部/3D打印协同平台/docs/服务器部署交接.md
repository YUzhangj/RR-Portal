# 服务器管理员部署交接

目标为单实例 PrintLink 平台；Windows 清溪电脑继续运行原 3d-server，现场桥接只读设备状态。此包不含业务数据库、用户密码、站点令牌、附件及历史资料，首次生产启动为空业务库。不要将开发演示数据库直接作为正式数据库。

本应用暂不纳入门户自动部署，不修改现有服务；管理员通过独立项目名 printlink 部署。需专用 HTTPS 根站点，尚未适配门户子路径和 SSO。

## 云端启动

在本目录准备 Docker 与 Docker Compose，创建仅管理员可读的 `.env`，填写首次 ADMIN_PASSWORD（至少 8 位），不要提交此文件。然后执行：

```sh
docker compose -p printlink up -d --build --no-deps platform
docker compose -p printlink logs --tail=80 platform
curl --fail http://127.0.0.1:3100/api/health
```

Compose 已固定生产模式，容器以 node 用户运行；业务数据位于持久化卷 platform-data 的 /app/runtime。平台只映射服务器回环端口 3100，生产内部服务 3102 不对外发布。管理员在服务器配置现有 HTTPS 反向代理，将选定站点转发至 http://127.0.0.1:3100。保持 Secure Cookie 默认设置。附件上传需相应调整代理的请求体限制与超时。

初始登录账号 admin，密码为首次启动时设置的 ADMIN_PASSWORD。后续修改环境变量不会重置已有账号密码。不要执行 docker compose down -v，以免删除业务卷。

## 采集站与清溪 Windows

按照 docs/stations.example.json 在持久化卷 /app/runtime/stations.json 设置实际采集站：名称清溪采集站，factories 为清溪、湖南、河源、印尼，machines 为实际授权机台，token 为各站独立随机令牌（至少 32 位）。该文件须让容器 node 用户可读，并限制其他用户读取。更改后重启容器。

示例令牌必须替换。未设置 stations.json 时有默认验收范围，不应直接用于正式现场。配置好真实采集站后，再向现场人员单独交付本站配置。Windows 按 docs/清溪Windows桥接接入.md 安装，legacy.url 在现场填写 http://127.0.0.1:3000（以实际旧系统端口为准），cloudUrl 填正式 HTTPS 根地址。不要将旧系统账号密码提交到 GitHub。

## 迁移、恢复与验收

需要迁移旧生产资料时，先备份并复核，在首次初始化前向持久卷提供 production-source.json 和 product-files；数据库已经初始化后不会重新导入该 JSON。历史订单迁移需另行核对，不自动复制开发数据。

备份必须停机，两个数据库和附件一起保存。工具为 ops/backup.mjs，参见 docs/备份恢复与上线准备.md。恢复只允许新目录，不覆盖现有数据；恢复后需重新登录。容器异常退出可能留下 .platform-lock：必须确认全部业务进程停止后才允许清理，不能在运行中删锁。

上线前检查：HTTPS 登录；四厂区权限；模型附件上传下载；清溪站点的设备与订单映射；打印状态、异常重打与绑定；质检扣库存幂等；交付和反馈；断网补传；备份恢复。正式切换后仅新平台做业务记账，避免与旧系统重复扣库存。

## 已验证和待验证

Node 本机回归覆盖订单权限、采集事件、入账、恢复、桥接接口等。容器构建、服务器部署、TLS 反代和 Windows 真机接入尚未验证。管理员应先建立独立测试环境；现有仓库结构在取得访问权限后再决定合入路径，不能直接覆盖其他应用。

HTTP 接入更新：现已支持显式 HTTP 开关，原有“必须 HTTPS”的说明适用于默认设置；用户选择 HTTP 时请按 [HTTP接入](HTTP接入.md) 操作。
