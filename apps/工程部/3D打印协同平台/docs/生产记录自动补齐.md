# 每日生产记录自动补齐

## 本次修复
Windows 原 3d-server 已经按真实设备状态自动建立打印批次；旧桥接仅上传设备状态，不上传这些记录。新桥接读取 `/api/version`，资料变化时读取 `/api/data`，仅提取每日记录的小字段，通过机台映射上传到云端。每 30 秒检查一次，设备状态采集不等待这项工作。无需持续打开浏览器。

首次启动会对映射机台的历史每日记录增量补齐（包括原有手工记录），之后持续追加新的批次并补充结束时间、失败结果及未被云端人工修改的工时。记录是否及时生成依赖原 3d-server 的自动记录功能保持运行；这是桥接模式的修复，不是另加一套打印机驱动。

- 原 JSON 已导入的记录按原 `_id` 匹配，不重复添加。
- 云端产品名称、材料、数量、备注等人工修改优先，不反向覆盖。
- 云端删除过的记录不因桥接重试恢复。原系统删除不会删除云端历史。
- 只上传记录字段，不上传图片、模型、产品库、材料库、库存快照、设置或密码。
- 记录使用现场机号，并保留平台机号、来源采集站信息。
- 新版云端首次启动时保存自动扣料启用时间，重启不会重置。启用后开始的自动采集记录（含关联订单），在材料、单件料重、数量完整且库存足够时，按料重 × 数量自动扣料并显示“已扣库存”。这使用记录中的用量，不代表打印机实测称重。
- 启用前的历史记录及没有打印开始时间的记录不自动补扣，防止重复扣减导入库存。库存不足或资料不全时仍显示“未扣库存”；补齐资料或入库保存时会再次检查。
- 同一记录重复同步、桥接或云端重启不重复扣料。扣料后普通编辑、删除记录不会自动退料，需通过库存调整核对差额。关联任务同样自动扣料，无需独立质检。旧版已质检结算的记录保留去重及抵扣保护。
- 此功能只更新云端材料库存，不回写 Windows 原系统；两边库存不再同步覆盖。部署只需更新云端，无需再次更新 Windows 桥接。
- 明确绑定云端任务且开始时间属于该任务的批次保留订单关联；旧版质检记录继续保留。没有明确绑定的历史记录不会按产品名猜测关联订单，需要人工核对。

## 更新顺序
1. 管理员合并本次 PR 并更新云端平台。
2. Windows 停止 PrintLink 桥接程序；原 3d-server 继续运行。
3. 备份桥接目录，将更新包内 `collector` 文件夹合并覆盖至 `D:\PrintLinkBridge\collector`（实际安装位置不同时使用原位置）。本次包仅含 `agent.mjs`、`records.mjs`、`console.js`。
4. 不删除、覆盖 `collector.json`、`bindings.json`、`outbox.sqlite` 或任何 runtime/data 目录，不修改原系统账号、令牌、IP、机台映射。
5. 按原方式重启桥接，在现场控制台 `http://127.0.0.1:3103` 查看“生产记录”状态、最后成功时间与已确认更新条数。失败会保留游标并重试。
6. 云端刷新“生产资料 → 每日记录”，选择 2026-10-09 核对条数和机台。若原系统仍为 70 条且均属于已映射机台，云端已有 30 条为同一来源且没有额外云端记录或删除，补齐后应为 70 条；额外云端订单记录、删除和未映射机台会影响总数，不能只用总数判断。

## 验证范围
自动化测试使用独立数据库和模拟原系统，验证 70/30 补齐、重复请求、重启游标、断网重试、字段白名单、保留云端修改/删除、机台授权及关联订单质检合并扣库。未连接现场 Windows，也未修改云端实际业务数据。安装更新后才会对现场数据执行补齐。


## 简化交付流程（取消独立质检步骤）

打印完成或管理员确认完成后，任务与订单直接进入待交付；确认交付只填写接收人、数量等说明。旧待质检任务在云端启动时自动迁移，不补造质检数据，也不因此额外扣料。

关联与未关联订单的自动采集记录使用相同的自动扣料规则（启用后的打印、用量完整、库存充足、同一来源仅扣一次）。采集的每日记录继续由 Windows 桥接同步，不再依赖质检表单生成；手动确认完成本身不会虚构耗材、工时或生产记录。历史未扣库存、缺少用量和库存不足的记录仍需在生产资料核对，不阻止交付。已完成的旧质检记录及扣料结果保留。

仅部署云端，Windows 桥接无需更新。
