# 现场统一记账：部署、切换与验收

## 数据归属

原 3d-server 是生产资料的唯一确认来源，包括产品、材料、每日记录、库存、出入库流水、排期、杂费、维修、费用设置和休息日。云端订单、账号及独立附件仍归云端管理。打印机实时状态继续由现场桥接上报，与业务记账分开。

云端生产页面显示现场已确认的副本。管理员通过 `/authority` 提交修改申请；请求持久化后显示“待现场确认”，不提前改变库存或报表。申请绑定已认证管理员、站点和既有桥接实例，编号不能改换归属或内容。现场按对象版本校验、保存业务数据和不可改写的回执后，云端才更新副本。某条申请因现场已修改而被拒绝，不阻断其他资料上报。刷新后重新提交新的申请即可；不要把失败申请当作已记账。

库存变动在现场执行一次，采用申请 ID 去重。丢失响应、桥接重启和重复投递均读取落盘回执。记录数量更正不会自动推算库存调整，实际领料/退料应另行按真实情况登记；库存申请输入正负克数，不能相加两边库存余额。

订单下发走独立持久队列，尚未收到现场回执时不标为已下发。既有排期按已确认版本关联，新的任务按外部任务 ID 更新；任务版本与采集事件序号分离，防止旧任务覆盖新状态；相同任务版本不能改换内容。下发排期不直接扣库存或生成生产记录。

## 部署顺序（云端和 Windows 都需要升级）

1. 云端管理员按现有独立应用部署流程部署本次 PR。代码上线不会自动切换现有业务。
2. 停止 Windows 桥接和原 3d-server。备份原系统整个目录（尤其业务数据、配置、附件）和桥接数据库；按现有备份流程备份云端生产与订单数据库及附件。备份目录应独立于升级包。
3. 将更新包的 `collector`、`legacy`、`shared`、`ops/lock.mjs` 文件合并到已有桥接程序目录；保留原 `collector/bridge.local.json`（或 `COLLECTOR_CONFIG` 指向的实际配置）、数据库、账号、令牌及机器映射，不使用示例配置覆盖它们。需要 Node.js 24 或更高版本。
4. 在桥接程序根目录执行：

   ```powershell
   node legacy/install-business-sync.mjs "D:\实际路径\3d-server"
   ```

   安装器会先检查原服务保存接口、实际 JSON 快照写入语句、旧页面版本保护及报表函数；不匹配时停止，不修改任何文件。所有待安装文件均先读取并校验语法。它安装适配器、回执保护及共享日报计算脚本，保留独立 `.printlink-install-日期-随机编号` 代码备份目录，其中包含每个被替换文件的旧版本和前后 SHA-256 清单；原有更早代码备份保持不动。快照写入改为同目录临时文件、文件 fsync 后原子替换；业务变化、资料版本及回执同在一份快照中，重启继续沿用已落盘的版本下限。Windows 不支持目录 fsync，仍需可靠磁盘及断电保护。这些代码备份不能代替业务数据库备份。不要在原服务运行期间安装。
5. 保留原配置中的 `businessSync: true`，停用旧主从同步；启动原 3d-server，再启动桥接。沿用现有站点、桥接数据库和机台映射，不新建桥接身份。
6. 管理员打开 `/authority`。切换前仍使用旧对账流程，先处理 `/business-sync` 中现存差异：保留双方真实产品；按现场真实库存核对；已主动删除的无效记录保持删除。新平台独有的有效资料须先合并进入现场。不能直接把整份云端资料丢弃。
7. 在业务修改短暂停止的窗口刷新对账，等待两边内容一致、新版现场快照在 60 秒内。完成备份勾选后点击“启用现场统一记账”。后端再次核对快照指纹，不一致则拒绝切换。云端保存一份切换前快照；切换快照独立保留，日常镜像另外保留最近五份覆盖前快照，因此长期恢复仍依靠第 2 步独立备份。
8. 等待下一轮现场确认。正常轮询间隔为 30 秒；大资料、网络或磁盘繁忙会延迟。生产页和统一记账页显示最后确认时间，超过 90 秒提示数据延迟。旧双向页面在切换后跳转到统一记账页。

## 使用变化

- 新平台原生产界面的直接保存、导入和旧桥接记账入口在切换后返回 409，并说明改用“统一记账”申请。独立产品附件继续使用原入口。
- 现场原 3d-server 仍可正常登记。管理员也可在云端申请新增、修改、删除资料和库存出入库。涉及历史引用的产品/材料重命名应在原系统操作。
- 云端查询最多返回 200 项，请用日期或名称缩小搜索范围。申请列表显示最近 100 条；数据库保留全部申请与回执。
- 两边日报使用同一份 `production-report.js`，统一北京时间日期、材料成本、机台历史数量及光固化费用。比较报表时选择相同日期范围，并确认云端“数据截至”已晚于现场最后修改时间。两边页面仍可选择不同查看周期。
- 断网不能保证两边即时一致；云端继续显示最后确认数据，申请排队，恢复网络后继续执行。此状态必须显示为延迟，不能作为已同步验收。

## 管理员验收

使用可撤销的测试资料，逐项记录申请 ID、源端落盘时间和云端确认时间：

1. 现场修改一条记录，云端本条内容和相同日期的日报一致。
2. 云端提交一笔库存调整：确认前余额不变，现场执行后两边一致，流水只出现一次。
3. 断网提交申请后恢复、重启桥接：申请只执行一次，不重复扣料。
4. 云端提交后，现场先修改同一对象：本申请被拒绝，其他记录和任务继续同步。
5. 原系统删除无效记录后，云端保留删除标记，不复活记录；产品双方有效资料仍在。
6. 检查既有订单不产生第二条排期，机台采用正确现场编号；较旧任务不覆盖新状态。
7. 两边选同一天/同月、相同设置与已确认数据，比较产值、材料、电费、人工和结余。打印机显示另核对现场 20 ↔ 平台 120 的映射与最后上报时间。

自动测试覆盖临时数据库、HTTP 权限、旧写入口阻断、丢响应重试、磁盘失败重试、任务重放及报表公式；无法代替 Windows 真机及线上历史账本验收。本次交付不自动修改线上数据或启用切换。

## 恢复边界

启用后不能直接降级到旧双向快照代码。必须先停止申请和桥接，导出未完成申请与最新两边资料，评估备份时点后的业务变动，再由管理员制定恢复方案。不要只恢复旧数据库而继续投递新请求，否则会破坏回执与实际账本的一致性。升级失败尚未启用时，可停机恢复安装器独立备份目录中的整组原代码及匹配配置；不要只恢复 server.js。发生安装异常时安装器会尝试恢复本轮全部原文件；若进程或主机中断，保持原服务停止，检查清单后由管理员整组恢复或重新安装。
