## 平台备份

以下命令均在 `本地整合版` 目录运行，适用于本机和使用 Node 启动的服务器。

1. 安排维护窗口，暂停业务操作。在启动平台的终端按 Ctrl+C，等待平台和生产服务全部退出。单独启动的采集程序可以保持运行并缓存上报；集成模拟程序随平台停止。
2. 创建备份父目录，指定一个尚不存在的目标目录：

```sh
mkdir -p backups
node ops/backup.mjs backup data backups/业务备份-日期时间
node ops/backup.mjs verify backups/业务备份-日期时间
```

3. 完成后使用 `npm start` 恢复本地验收；正式环境使用其既有生产环境变量和 `npm run cloud`。确认登录、订单、生产资料以及采集站恢复正常。

正式部署时，用实际 `PLATFORM_DATA_DIR` 替换命令中的 `data`。不要将备份放入源数据目录中。工具包含两个业务数据库、订单附件、产品附件及数据目录内站点/服务配置，排除本地 `collector/` 队列和生成的模拟 `collector.json`；现场电脑配置、设备凭据和采集队列需在现场另外保存。

备份包含账号密码摘要和站点令牌，文件采用仅当前账号可读写权限；文件本身未加密。正式备份应保存到受控的独立磁盘或备份存储，不放入 Git。SHA-256 清单用于发现损坏，不是数字签名。当前备份与源数据仍在同一台电脑，不能抵御整机故障。

## 恢复至新目录

```sh
mkdir -p recovery
node ops/backup.mjs verify backups/业务备份-日期时间
node ops/backup.mjs restore backups/业务备份-日期时间 recovery/业务恢复-日期时间
```

恢复拒绝覆盖已有目录。原账号和密码保留，旧浏览器会话清除。恢复不会将演示数据库转换成正式数据库。

本地演示副本验证：

```sh
PLATFORM_DATA_DIR="$PWD/recovery/业务恢复-日期时间" PORT=3190 PRODUCTION_PORT=3192 node start.mjs --cloud-only
```

打开 http://127.0.0.1:3190/platform 核对用户、订单、附件、库存和生产记录。关闭副本后再决定是否切换；不要让两个业务实例同时接收正式订单，也不要启动两份相同采集站。正式数据恢复时必须保留 `APP_MODE=production` 并通过正式 HTTPS 入口登录。

## 目录锁与异常退出

请统一通过 `start.mjs`（或 npm start / npm run cloud）启动业务，禁止绕过入口单独运行 cloud/server.mjs 和 production/server.js，否则会绕过平台备份锁。独立现场采集不受此限制。

运行中备份被拒绝。正常停止会在两个业务子进程退出后释放 `.platform-lock/`。异常断电或强制结束后，锁可能保留；先确认平台、生产服务全部停止，再人工清理对应数据目录的 `.platform-lock/`。不得在服务运行时删除锁。备份必须在业务停止后进行，不提供热备份。

## 下一次正式接入需要的条件

- 云服务器系统、域名、已配置的 SSH 访问方式；当前仅知道服务器地址，未执行远程连接。
- HTTPS 入口、服务自启动、生产数据目录和首次管理员密码；演示数据与正式数据分开。
- 每个现场的独立采集站令牌、厂区范围和全局唯一机台编号。
- 先选择一台真实打印机，在现场配置设备地址和凭据，完成空闲绑定、打印、异常重打、断网补传和人工质检核验。
- 正式上线前，将备份存到独立存储并进行一次正式数据恢复演练。Docker 部署模板本阶段只更新打包内容，尚未实际构建和云端验证。

密码和设备密钥应保存在服务器或现场电脑的受控配置文件中，无需发到聊天里。
