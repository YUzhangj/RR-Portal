# 清溪 Windows：复用原 3d-server 的采集

本方案只读原系统 GET /api/printers，不重新连接打印机，不调用扫描、打印、库存或业务写入接口。原系统继续采集，桥接进程使用其登录账号读取状态，再使用独立站点令牌向平台上报。账号与密码只放在 Windows 本机配置中。

## 当前完成与限制

桥接代码已在 Mac 上使用模拟原系统接口测试，包括 Basic 认证、机台编号映射、过期状态过滤、请求失败转离线及敏感字段不转发。尚未在 Windows 和真实打印机上联调。原系统提供的 lastUpdate / lastSeen 超过 30 秒时，桥接将设备视为离线；这依赖现场电脑时钟及原系统更新时间正确。

状态仅采用 IDLE、RUNNING、FINISH、FAILED、PAUSE、ERROR；其他值显示 UNKNOWN，不猜测。光固化若已在原接口提供相同字段也可读取，但仍需实测其状态含义。

## 平台侧准备

平台站点设置为“清溪采集站”，授权厂区清溪、湖南、河源、印尼，以便清溪承接各厂区订单。这里的厂区列表是订单访问范围，打印机实际仍在清溪。machines 填入实际授权的全局机台编号，各站使用不同令牌。

参考 docs/stations.example.json，在平台数据目录中配置 stations.json，重启平台生效。不要直接使用示例令牌或在已有任务仍运行时随意更换站点 ID。试接应建立单独试验站、使用未占用的全局机台编号，避免混用模拟采集站。

Windows 必须能访问平台 HTTPS 地址。目前 Mac 上的 http://127.0.0.1:3100 仅本机可用，不能原样填到 Windows。先部署可访问的 HTTPS 测试平台，再在现场启用桥接。

## Windows 操作

1. 将 Windows桥接包.zip 解压至 C:\PrintLinkBridge。安装 Node.js 24 或更高版本，确保终端运行 node --version 有输出。不需要 npm install。
2. 将 collector\bridge.example.json 复制为 collector\bridge.local.json。
3. 填写 cloudUrl（HTTPS 平台根地址）、平台分配的 token、原系统本机访问地址和登录账号密码。示例原系统端口 3000 只是占位，须填写 Windows 上实际使用端口。
4. machineMap 表示“原系统机台编号 → 平台机台编号”，例如 {"1":"101","2":"102"}。只列出准备试接的机台；映射后的编号必须在本站授权中。
5. bindingsFile 填本机绝对路径。若使用默认 C:/PrintLinkBridge/runtime/bindings.json，启动脚本会创建 runtime 目录。改到其他目录时需先创建其父目录。
6. 双击 collector\启动Windows桥接.cmd。脚本先检查配置及平台授权，再启动桥接。不要重复启动同一采集站，也不要同时启动相同站点的模拟采集。
7. 在 Windows 浏览器打开 http://127.0.0.1:3103/ 查看设备和平台连接。平台管理员同时在“设备采集”确认清溪机台状态。

旧系统密码与平台令牌不同，均不要提交到代码仓库或发到聊天。控制台不显示密码。该进程须与原 3d-server 运行在同一台 Windows 电脑，原系统地址只允许回环地址。

## 首次验证

先只看设备状态，核对空闲、打印中及完成与原系统一致。之后用测试订单安排映射后的机台，在现场控制台趁设备在线空闲确认本轮任务绑定，再正常操作打印机。桥接不会发送文件或启动打印。完成后核对待质检，再人工确认质量和耗材；重打需重新绑定轮次。

如原系统仍在记录真实生产和库存，本轮先验收状态同步，不要在两套系统同时做正式耗材入账。正式业务切换前明确唯一记账系统。

关闭桥接终端即可停止桥接，原系统仍继续采集。桥接队列保存在 runtime，保留该目录可在重启后补传；不要删队列或更换令牌去复用另一站点。

HTTP 接入更新：现已支持显式 HTTP 开关，原有“必须 HTTPS”的说明适用于默认设置；用户选择 HTTP 时请按 [HTTP接入](HTTP接入.md) 操作。
