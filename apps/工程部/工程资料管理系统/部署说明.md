# 部署到服务器说明

系统是一体化的：前端网页 + 后端 API 在同一个服务里，端口 **3100**。
服务器只要能跑 Docker 或 Node.js（20+），并且能访问到「工程资料」文件夹即可。

---

## 方案 A：部署到群晖 NAS（推荐）

你们的资料本来就在 NAS（NAS2）上，把系统直接跑在 NAS 上最合理：
数据不用过任何中转，24 小时在线，不依赖任何人的电脑。

前提：NAS 支持 Container Manager（DSM 7.2+，套件中心免费安装）。

1. 套件中心安装 **Container Manager**
2. 用 File Station 把整个 `工程资料管理系统` 文件夹上传到 NAS（任意位置，如 `docker/gongcheng-docs`）
3. 开启 NAS 的 SSH（控制面板 → 终端机和 SNMP），SSH 登录后执行：

```bash
cd /volume1/docker/gongcheng-docs
docker build -t gongcheng-docs .
docker run -d \
  --name gongcheng-docs \
  --restart always \
  -p 3100:3100 \
  -v /volume1/<XX共享文件夹的实际路径>/工程部/工程资料:/data \
  -e DOCS_ROOT=/data \
  gongcheng-docs
```

4. 浏览器访问 `http://<NAS的局域网IP>:3100/`

> 注意把 `-v` 里的路径换成 XX 共享文件夹在 NAS 上的真实路径
> （File Station 里右键文件夹 → 属性可以看，一般是 `/volume1/共享文件夹名/工程部/工程资料`）。

---

## 方案 B：部署到任意一台常开的电脑 / 服务器（Windows 除外需装 Node）

适用于：公司里另一台一直开机的 Mac / Linux 主机。

```bash
# 1. 挂载 XX 网络盘（macOS: Cmd+K 连接 smb://116.6.84.98/XX；Linux 用 cifs 挂载）
# 2. 安装 Node.js 20+ 后：
cd 工程资料管理系统
npm ci
npm run build
DOCS_ROOT="/挂载点/工程部/工程资料" npm run preview
```

访问 `http://<服务器IP>:3100/`。要长期运行可用 pm2 / systemd / launchd 守护。

---

## 方案 C：继续用这台 Mac（现状）

已经在跑：launchd 常驻服务 + 开机自启，地址 `http://<本机IP>:3100/`。
适合过渡期使用，缺点：这台 Mac 关机或断网，大家都用不了。

---

## 部署后验证清单

- [ ] 打开首页能看到客户卡片（说明读到了资料目录）
- [ ] 顶部没有黄色「资料根目录不可用」警告
- [ ] 进一个项目 → 从模板新建一份资料 → 在 File Station / 访达里确认文件真实生成

## 数据安全说明

- 系统不建数据库，所有资料直接读写挂载的资料文件夹
- 删除操作一律进 `.回收站` 文件夹，可还原
- 系统本身没有账号密码，请只在内网使用
