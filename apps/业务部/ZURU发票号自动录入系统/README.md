# ZURU 发票号自动录入系统

上传排期 Excel，自动匹配并填入发票号，输出新文件（不改原件）+ 分类清单。精确度优先：拿不准的一律不填、转人工。

## 功能

- 支持**总排期**（固定列：D=PO号、E=客PO、F=SKU行号、G=货号#、I=PO数量、M=走货期、AC=发票号）和**分排期**（每个 sheet 独立识别列，支持「發票號」繁体、「客户 PO 号」、「计划出货期」等表头）
- 发票库自动建库：上传发票文件自动识别两种格式——
  - **逐张发票格式**（sheet-per-invoice：sheet 名=发票号，内含 PO NO / 货号 / 数量 / 开票日期）
  - **ZB 汇总表格式**（首张 sheet 为累计汇总表 + 实体发票 sheet，含 Ultimate consignee PO#）
  - 重复/累计文件自动以最新版为准
- 输出 Excel 颜色语义：
  - **粉色** = 系统确定填入（分排期按惯例写 `发票号-月.日` 并同步「是否已入系统」列）
  - **绿色** = 不确定，候选发票号已写在格子里，人工定夺后直接改
  - 空白 = 发票库无记录（未出货/未开票）
  - 原有发票号的行**一律跳过不覆盖**

## 匹配规则（精确度优先）

1. PO 精确匹配为前提；货号提取候选（4-6 位数字段 + 含字母完整段如 MEC251）
2. 多张候选发票时按 数量 → 日期 消歧；同货号分批出货且数量合计吻合时合并填入（票1/票2）
3. 客 PO（Ultimate consignee PO#）参与匹配与分组：同 PO 同货号不同客 PO 分开算
4. 禁止 PO 级回退误填：货号对不上就不填
5. 整票闭合补齐：唯一发票数量与排期待填行合计分毫不差时自动补填
6. 供给护栏兜底：发票货号数量不够排期行分时整组转人工，杜绝"入多"

## 部署

### Docker（推荐）

```bash
cd apps/业务部/ZURU发票号自动录入系统
docker build -t invoice-filler .
docker run -d --name invoice-filler -p 5010:5010 \
  -v $(pwd)/data:/app/data -v $(pwd)/output:/app/output \
  -e APP_TOKEN=你的访问口令 \
  invoice-filler
```

### 直接运行

```bash
pip install -r requirements.txt
python app.py --host 0.0.0.0 --port 5010
# 或双击 启动系统_Windows.bat / 启动系统_Linux_Mac.sh（自动建 venv）
```

环境变量：`PORT`（默认 5010）、`APP_TOKEN`（设置后需口令登录，多人共用建议开启）。

## 使用

1. **建库**（首次/发票更新时）：页面①上传发票文件（两种格式混传、自动识别），等待 2-4 分钟
2. **日常**：页面②上传排期 → 下载「已入发票排期」和「分类清单」
3. 「需人工复核」sheet 与绿色格子一一对应，逐行附候选发票号

## 目录

| 文件 | 作用 |
|---|---|
| `app.py` | Flask + Waitress 服务 |
| `matcher_unified.py` | 匹配逻辑（2025 发票原件 + ZB 汇总表 + 客 PO + 数量护栏） |
| `build_db.py` | 发票文件自动识别与发票库构建 |
| `process_schedule.py` | 排期列识别、逐行分类、写入与着色 |
| `data/` | 发票库缓存（不上库，部署后通过页面上传发票文件生成） |
| `uploads/ output/` | 运行时目录（不上库，定期清理） |
